# Wilai Communities

ระบบจัดการหอพักในเครือวิไล — Next.js 15 + Firebase + Tailwind v4

ข้อมูลทั้งหมดจากวิไลเพลส V2 (17 ห้อง) ย้ายเข้ามาแล้วในชื่ออาคาร **วิไลเพลส 1**
โครงสร้างรองรับหลายอาคารตั้งแต่ต้น เพิ่มอาคารที่ 2 ได้โดยไม่ต้องแก้ schema

อ่าน [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) ก่อนแก้โครงสร้างข้อมูล

## เริ่มใช้งาน

```bash
npm install
npm run dev        # เปิด http://localhost:3000
```

ครั้งแรกยังไม่ต้องตั้งค่าอะไร แอปจะเข้า **โหมดสาธิต**: อ่าน `data/v2-export.json`
แปลงด้วยตัวแปลงตัวเดียวกับสคริปต์ย้ายข้อมูลจริง แล้วเก็บผลที่ `data/local-store.json`
กดปุ่ม "เข้าใช้งาน (โหมดสาธิต)" แล้วเลือกอาคาร → เห็นข้อมูลจริงของวิไลเพลส 1 ทั้งหมด

ลบ `data/local-store.json` เมื่อไหร่ก็กลับไปเป็นข้อมูลตั้งต้นจาก V2 ใหม่

## ต่อ Firebase ของจริง

```bash
cp .env.example .env.local     # เติมค่าให้ครบ
```

ใน Firebase Console:

1. เปิด **Authentication → Google Sign-in**
2. สร้าง collection `allowlist` เพิ่ม document id เป็นอีเมลคุณ (ตัวพิมพ์เล็ก)
   ```
   { role: "owner", name: "ชื่อคุณ", propertyIds: [] }   // propertyIds ว่าง = ทุกอาคาร
   ```
   หรือจะข้ามขั้นนี้ก่อนก็ได้ โดยใส่อีเมลไว้ใน `OWNER_EMAILS` ของ `.env.local`
3. Deploy rules
   ```bash
   firebase deploy --only firestore:rules,storage:rules
   ```

พอ `.env.local` ครบ ปุ่มโหมดสาธิตจะหายไปเองและเหลือแค่ปุ่มเข้าสู่ระบบด้วย Google

## ย้ายข้อมูล V2 ขึ้น Firestore

```bash
npm run migrate:v2 -- --dry-run    # ดูก่อนว่าจะย้ายอะไรบ้าง ไม่เขียนอะไรทั้งนั้น
npm run migrate:v2                 # เขียนจริง (ข้ามเอกสารที่มีอยู่แล้ว)
npm run migrate:v2 -- --force      # เขียนทับของเดิม
```

สคริปต์ตั้งเลขรันต่อจากของเดิมให้ด้วย (bill 26, invoice 26, receipt 23) เลขจึงไม่ขาดช่วง

`data/v2-export.json` คือสแนปช็อตชีต V2 คอลัมน์ตรงกับชีตเดิม ถ้าจะย้ายรอบใหม่ให้ export ทับทั้งไฟล์

**ตัวแปลงไม่ซ่อมข้อมูลเงียบๆ** จุดที่ชีต V2 ไม่ตรงกันจะถูกบันทึกไว้และแสดงในหน้าตั้งค่า
ข้อมูลชุดปัจจุบันมี 6 จุด เช่น รหัส `T0013` ถูกใช้ซ้ำกับผู้เช่า 2 คน (ออกรหัส `T0018` ให้แทน)
และห้องที่ V2 ไม่ได้กรอกชื่อผู้เช่าไว้

**หลังย้าย:** เปิด V2 ไว้แบบอ่านอย่างเดียวสัก 1 เดือน เผื่อต้องย้อนดู

## หน้าจอ

| เส้นทาง | ทำอะไร |
|---|---|
| `/login` | เข้าสู่ระบบด้วย Google (หรือโหมดสาธิต) |
| `/select` | เลือกอาคารในเครือ · เจ้าของเพิ่มอาคารใหม่ได้ |
| `/` | หน้าหลัก — สรุปภาพรวม กราฟอัตราเก็บเงิน ยอดค้างแยกตามอายุหนี้ ความเคลื่อนไหวล่าสุด |
| `/property` | ผังห้องแยกตามชั้น · สรุปรอบปัจจุบัน · รูปอาคาร |
| `/rooms/[roomId]` | ผู้เช่าปัจจุบัน สัญญา มิเตอร์ล่าสุด ประวัติบิล |
| `/tenants`, `/tenants/[id]` | รายชื่อผู้เช่าพร้อมรูป · **อัปโหลดรูปผู้เช่าได้** · สัญญาและบิลรายคน |
| `/meter` | จดมิเตอร์ทั้งตึกหน้าเดียว → ออกบิลรวดเดียว ยกยอดค้างเดิมให้อัตโนมัติ |
| `/bills`, `/bills/[id]` | รายการบิล กรองตามรอบ/สถานะ · รับชำระ · ยกเลิกบิล (void ไม่ลบ) |
| `/payments` | บิลที่รอเก็บ · เงินสดรับรายเดือน · ใบเสร็จล่าสุด |
| `/maintenance` | แจ้งซ่อมและติดตามสถานะ |
| `/settings` | แก้ข้อมูลอาคาร + รูปอาคาร · ดูจุดที่ข้อมูล V2 ไม่ตรงกัน · ออกจากระบบ |
| `/invoice/[billId]` | ใบแจ้งหนี้สาธารณะ ผู้เช่าเปิดจากลิงก์ได้โดยไม่ต้องล็อกอิน |

## หลักการที่ไม่ควรละเมิด

1. **ข้อมูลมีที่อยู่ที่เดียว** — อยากรู้ว่าใครอยู่ห้องไหน ตาม `activeLeaseId` เสมอ ห้ามเก็บชื่อซ้ำในห้อง
2. **บิลลบไม่ได้** — ยกเลิกได้ (void) แต่เลขรันต้องไม่ขาดช่วง
3. **ทุกการเขียนมี audit log** — ไม่มีข้อยกเว้น
4. **cycle เป็น string 6 หลักเสมอ** — บั๊ก V2 ที่เสียเวลาแก้นานที่สุดมาจากเรื่องนี้
5. **ความลับอยู่ฝั่ง server** — client เขียน Firestore ตรงๆ ไม่ได้ ทุกอย่างผ่าน API
6. **ทุกเอกสารมี `propertyId`** — ไม่งั้นข้อมูลข้ามอาคารกันแน่นอน

## ที่ยังไม่ได้ทำ

- LINE: ส่งบิลเข้าไลน์ + webhook รับสลิป (โครงข้อมูลเตรียมไว้แล้ว)
- SlipOK: ตรวจสลิปอัตโนมัติ (`payments.slip` เตรียมที่ไว้แล้ว)
- เพิ่ม/ย้าย/ปิดสัญญาผู้เช่าจากในแอป
- บันทึกค่าใช้จ่ายและรายงานกำไรขาดทุน
